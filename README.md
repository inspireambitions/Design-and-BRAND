# Ascent — career transition planning

A premium career-change tool. Answer eight questions, get a twelve-section
month-by-month roadmap: skill gaps, budget-filtered courses, portfolio projects
built on your existing career, salary progression, an interview narrative, an
honest risk assessment, and a first-90-days plan.

Built with Next.js 16 (App Router), TypeScript, and Tailwind. Roadmaps are
generated by Claude when an API key is present, and by a local deterministic
engine when it isn't.

---

## Running it

```bash
npm install
npm run dev          # http://localhost:3000
```

That's the whole setup. **No API key is required** — see below.

Production:

```bash
npm run build && npm start
```

---

## Does it need an API?

No. There are two generation paths and the product is complete on either.

**Without `ANTHROPIC_API_KEY` (default).** `lib/engine.ts` generates the full
twelve-section report locally from `lib/careers-data.ts`, a curated dataset
covering eight common target roles with real course names and prices, salary
bands, named communities, and day-in-the-life detail. It scores the match from
transferable skills, weekly hours, timeline, and role difficulty; filters
courses against the stated budget; and builds a four-phase schedule from the
chosen timeline. Everything renders. The only thing disabled is the coach chat,
which says so plainly rather than failing silently.

**With `ANTHROPIC_API_KEY` set.** `/api/roadmap` calls Claude Opus 5 with a
JSON schema (`lib/schema.ts`) so the response is guaranteed to parse, and the
coach chat becomes live. This path writes genuinely bespoke content — it can
reason about *your* specific "teacher → UX" leverage rather than selecting from
a dataset, and it handles target roles the dataset has never seen.

```bash
cp .env.example .env.local   # then add your key
```

The engine stays wired as the safety net: if the API call fails, refuses, or
returns something malformed, the route serves the engine report instead of an
error. A user never sees a broken page because of an upstream problem.

## Structure

```
app/
  page.tsx              Landing page
  start/                Eight-step intake wizard
  report/               The report, preview + paywall + full
  careers/              Career library with salary and difficulty data
  api/roadmap/          Generation endpoint (Claude → engine fallback)
  api/coach/            Follow-up chat, grounded in the user's report
components/
  HeroPreview.tsx       Miniature of the real report, used on the landing page
  Wizard.tsx            Intake flow + generation screen
  report/               Report sections, paywall, coach drawer
lib/
  engine.ts             Deterministic report generator (the no-key path)
  careers-data.ts       Curated role knowledge: courses, salary, communities
  prompt.ts             System + user prompts for the Claude path
  schema.ts             JSON schema for structured output
  types.ts              Shared types and section metadata
  brand.ts              Name, price, guarantee — rebrand in one file
```

## Payments

`ReportView.unlock()` is a demo stub that flips a session flag. To take real
money, replace it with a Stripe Checkout redirect and set the unlock flag only
after the webhook confirms payment — the flag should never be client-writable
in production.

## Notes

- Report state lives in `sessionStorage` (`lib/storage.ts`). No accounts, no
  database, nothing to leak. Add persistence when you add auth.
- The full report prints cleanly to PDF via the browser (`@media print` rules
  in `globals.css`); the "Save as PDF" button calls `window.print()`.
- Salary figures are market estimates. The report says so where they appear.
